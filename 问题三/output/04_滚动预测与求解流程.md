# 问题3滚动预测与求解流程

## 1. 总体框架

> 历史已实现信息 → 0点建立原始合同B → 逐10分钟物理执行 → 6/12/18点接收新PV vintage → 绝对target对齐 → 更新因果负荷预测/历史场景 → 信息节点共享的多阶段LP → 仅修订未交付合同 → SOC连续传递 → 次日0点重新建B。

## 2. 1月暖启动

2025-01-01以 $S_0=6000$ kWh启动。1月每个事件都走同一套因果逻辑，历史不足时场景数自然减少；SOC持续递推。2月1日直接继承1月31日24:00状态，不重置。

## 3. 每天0点

1. 自然日00:00—00:10继续执行前一计划日末合同槽；
2. 读取0点合法forecast vintage与历史信息；
3. 建立负荷/PV点预测和历史analog场景；
4. 求事件LP，生成144槽原始合同 $B_d$；
5. 永久留痕 $B_d$ 并设 $A_{d,0}=B_d$。

## 4. 6/12/18点事件

事件发生前先执行完上一10分钟区间并更新真实SOC。随后接收当前新PV vintage，按绝对target time对齐；只用已完成负荷残差修正负荷预测；从 $d-2$ 及更早成熟历史构造最多3场景；按未来信息揭示路径生成稀疏场景树；保持已交付合同前缀冻结；求多阶段LP并只写回当前节点合法后缀；以新的期望SOC轨迹执行下一段。

18点以后进入次日的变量只用于continuation，不写成次日合同。

## 5. 日终与次日

记录最终 $A_d$、充放电、紧急购电、弃电与SOC，令
$$S_{d+1,0}=S_{d,24:00},$$
下一日0点重新生成新 $B_{d+1}$。

## 6. A/B/C/D因子实验

| 组别 | 使用6/12/18新PV vintage | 合同可修订 |
|---|---|---|
| A | 否 | 否 |
| B | 是 | 否 |
| C | 否 | 是 |
| D | 是 | 是 |

D为最终主模型。四组共享数据、负荷预测、场景逻辑、储能与结算，只切换这两个开关。

## 7. 伪代码

```text
SOC = 6000
for d = Jan-01 ... Dec-31:
    执行自然日00:00-00:10的昨日末合同槽
    at 00:00:
        构造合法信息集和0点PV vintage
        构造因果场景树
        B[d] = solve_event_LP(...)
        A[d] = B[d]
    for tau in {6,12,18}:
        先执行至tau并更新真实SOC
        接收vintage(tau)，按绝对target对齐
        构造仅依赖已实现历史的场景树
        冻结已交付合同前缀
        A[d] = solve_event_LP(B[d], A[d], ...)
    执行至24:00
    SOC传给下一自然日
仅汇总 Feb-01 ... Dec-31 为正式评价
```
